# C题第一至三问：可复现代码与结果

本目录统一实现第一、二、三问的输入读取、模型运行、官方模板输出和验证。默认附件目录为本目录下的 `附件/`；所有入口均可用 `--attachment-dir` 指定另一份同结构数据。第四问按当前项目范围排除。

## 环境与运行

```powershell
python -m pip install -r requirements.txt
python run_q1.py
python run_q2.py
python q3_model.py
python validate_project.py
```

默认输出分别位于 `output/q1/`、`output/q2/`、`output/q3/`。正式工程基线和模型对照保存在 `output/engineering_baseline/` 与 `output/model_versions/`。`validate_project.py --rerun` 会重新执行全部第一至三问及已定义的对照实验，随后验证输入、约束、模板与费用回归；普通运行只验证已有结果，耗时更短。

依赖为 NumPy、SciPy、Matplotlib 和 openpyxl。结果工作簿直接加载附件5中的官方 `result1.xlsx`、`result2.xlsx`、`result3.xlsx` 后填值，保留其工作表结构和格式。

## 统一数据和校验

`project_io.py` 要求：附件1为144个十分钟点；附件2为2025年连续365天、每天144点；附件3完整覆盖365天与0/6/12/18点四个发布时间、每条24小时预测。日期重复或缺失、发布时间重复或缺失、空白、非数值、NaN、无穷值和负值均直接报错，不再转换为零。

当前统一验证包含148项检查，全部通过。检查范围包括四类错误输入失败测试、结果工作表名称、334天日期、逐日及全期电量和费用、SOC范围、能量平衡残差、充放电重叠、极端缺电和光伏过剩压力测试，以及三问工程基线费用回归。

## 问题1

问题1采用确定性单日线性规划。每个十分钟时段满足：

`g_t + pv_t + r_t = load_t + c_t + spill_t`

`E_t = E_(t-1) + 0.9*c_t - r_t/0.9`

初始与日终储电量均为6000 kWh，SOC范围为1200—10800 kWh，充放电功率上限为5000 kW，即每个十分钟最多833.3333 kWh。当前结果为：

| 指标 | 数值 |
|---|---:|
| 正常购电量 | 59,482.6990 kWh |
| 正常购电费用 | 35,126.9486 元 |
| 充电量 | 20,740.6661 kWh |
| 放电量 | 16,799.9396 kWh |
| 最大能量平衡残差 | 2.27e-13 kWh |

## 问题2

问题2在0点用历史数据形成次日计划；正常购电计划固定，实际运行时储能基于当前十分钟实测供需闭环调整，剩余缺口按当时电价的5倍紧急购电，剩余过剩电量弃置。2月1日至12月31日共334天的费用口径为：

`C2 = sum(p_t*g_t) + 5*sum(p_t*emergency_t)`

### 严格因果1月初始化

`run_q2.py` 从1月1日起只使用决策时已知信息，默认采用零计划冷启动；`run_q2_causal.py` 用于显式运行两种对照。两种冷启动都完整保留：

```powershell
python run_q2_causal.py --cold-start zero
python run_q2_causal.py --cold-start baseline
```

- `zero`：1月1日没有历史信息时令正常购电计划为零，用当前实测供需和储能执行，剩余缺口紧急购电。这是信息边界最严格的主版本。
- `baseline`：仅在1月1日使用附件1中的一天负荷和光伏曲线作为事先给定的代表性基准，之后改用当时已经积累的历史数据。这是冷启动敏感性对照。

两种冷启动的一月运行费用分别为2,634,657.8281元和2,489,874.2811元，相差144,783.5470元；到2月1日时二者都收敛到10,450.3523 kWh，2—12月结果完全相同：

| 指标 | 因果零计划 | 因果基准曲线 |
|---|---:|---:|
| 正常购电费用 | 16,289,477.6578 | 16,289,477.6578 |
| 紧急购电费用 | 2,407,040.8301 | 2,407,040.8301 |
| 紧急购电量 | 405,289.3713 | 405,289.3713 |
| 总费用 | **18,696,518.4879** | **18,696,518.4879** |

因此冷启动选择影响1月热身过程，但在当前数据和模型下不影响题目要求的2—12月答案。与工程基线相比，严格因果版本总费用低2,145.3354元；该差异来自初始化模型变化，应作为独立模型版本报告。

## 结果使用规则

工程基线用于回归，不代表所有建模假设均已验收。第二问论文主结果应采用严格因果零计划版本，并同时报告基准曲线冷启动对照。第三问当前主版本采用0/6/12/18点累计更新、终端价值系数0。论文源文件未包含在项目中，因此本次只更新代码、README和结果表；将数值写入论文时应直接引用各版本 `summary.json` 或模型对照表，避免手工抄录旧值。
