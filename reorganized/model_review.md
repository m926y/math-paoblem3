# 原方案审查结论

## 问题1

原 `main.py` 的核心约束可以解释为：每个十分钟内，外网购电、光伏和储能放电共同满足负荷与储能充电；储能以 `E_{t+1}=E_t+0.9c_t-d_t/0.9` 更新；充放电上限为 `5000/6 kWh`；日初和日终储能均为 6000 kWh。这部分量纲和主约束是正确的。

需要修正或补充的地方：

- 原程序依赖 `pulp`，但没有提供稳定的依赖和求解状态检查；整理版改用 `scipy.optimize.linprog`，避免不必要的 Gurobi/PuLP 依赖。
- 原程序没有弃电变量。由于题目没有给出上网电价，光伏过剩应允许弃电；否则模型可能不可行或被迫错误充电。
- 原程序输出结构与 `附件5/result1.xlsx` 不完全一致。整理版按模板写出“计划购电量”和“充放电量”，并单独保存数值检查报告。

## 问题2

原 chat 中的两阶段模型存在结构性错误。它使用同一个 `g,c,d,E` 同时满足：

`g+pv_safe+d=load_safe+c`

和

`g+pv_real+d+emergency=load_real+c`。

这不是“日前计划 + 实际运行”的两阶段决策，而是要求同一组动作同时适配两套数据。它还没有实际过剩时的弃电变量，并把当天实际值直接放入优化问题，造成未来信息泄漏。

原预测误差也不成立：

- `load[day-1]-load_pred` 把前一天的实际值与当天的预测值相减，日期错位；
- `for i in range(day)` 中得到的 `lp` 没有被使用；
- 误差样本没有按每个历史目标日重新生成滚动预测；
- 输出从数组第 8 天开始，而模板要求从 2025-02-01 开始。

整理版采用如下闭环：

`历史实际数据 -> 7日加权预测 -> 80%单侧安全裕度 -> 日前调度计划 -> 固定计划实际仿真 -> 紧急购电/弃电`

实际负荷和光伏只出现在最后的仿真环节，不参与当天计划求解，因此没有偷看当天实际值。由于题目未规定储能在实际偏差下能否临时调整，整理版采取“计划充放电固定、缺口由紧急购电补足、过剩弃电”的明确约定；如论文采用可调整充放电策略，应另建含实时再调度变量的模型，不能直接复用原代码。
